# Encoder / CC Mode (ENCMODE)
- **ENC1–ENC4** send **CC 17–20** on `encChannel` (default ch1, set by the locked step-pad picker of plain ENCMODE, or momentarily in variant 3; a KEYMODE3 **ENCOD lock** links it to the SEQ edit channel — see Keyboard Playing)
- **ENC5–ENC8** send the current **F-bank** block inside the active **M3 page group**: group 1 (M3 off) = **F1 = CC 1–4**, **F2 = CC 5–8**, **F3 = CC 9–12**, **F4 = CC 13–16**; group 2 (M3 on) = **F1 = CC 21–24**, **F2 = CC 25–28**, **F3 = CC 29–32**, **F4 = CC 33–36**
- **The map is a file you can edit**: `CcConfig.h` holds the four fixed CCs (`CC_ENC_FIXED`) and the 4×4 block per page group (`CC_ENC_BANK`), and `encCcNum()` only looks the numbers up there — so a remap moves the MIDI send, the dial captions and the `CC CONFIG` page together. Entries must stay in **CC 1–36**, the range the per-CC-per-channel value store holds (a hand-edited number outside it is clamped). The numbers above are the defaults
- **F1–F4** = CC-bank radio, and each button is labelled with **that bank's row FLAVOR** — `DIAL` / `LEVEL` / `ENV` / `LFO` (see ENCMODE4 below), so the strip names how its own pad draws the second row; the fill still marks the armed bank (bright white = armed; always one armed — **remembered per encoder channel and persisted with SEQMODE4+REC**: switching the encoder channel, or re-entering ENCMODE, recalls that channel's last bank + page group). Idle color follows the page group: dim purple in group 1, dim medium sea green in group 2. In ENCMODE the F row leaves the inherited KEYMODE2 chord-extension job
- **M3 (PAGE)** = page-group toggle: dim medium sea green = group 1 (CC 1–16), purple = group 2 (CC 21–36); off on first entry (also leaves the inherited KEYMODE2 chord-quality job)
- Values persist across mode changes (0–127, clamped, no wrap); DAW feedback on CC 1–36 syncs the matching knobs
- Knob positions are stored **per CC number × channel** (36×16): switching the encoder channel loads that channel's own values instead of inheriting the previous channel's (no jump)
- **Screen (ENCMODE 1/2/4)**: the eight knobs are drawn as **270° dials** in a 4×4 grid — **dial, CC number, dial, CC number** — so the value sits *inside* its ring and the CC number underneath it. A dial is a **radius-9 ring drawn as a single-pixel arc** (`u8g2.drawArc`, 90° gap at 6 o'clock: 0 at the lower-left end, 127 at the lower-right) with a **4-px-long, 2-px-wide pointer that reaches one pixel outside the rim** at the current value (a *second* Bresenham pass one pixel across — on the upper side, so it can never grow down into the CC caption in the ring's bottom notch), and the 0–127 value in the middle. The CC number under each dial is set in the **4×6 caption font** (`u8g2_font_micro_tr` — 15×5 px, between the 3×3 that was unreadable and the 5×7 that shouted), centred under its ring, and its ink falls in the ring's open bottom notch: 1 px below the arc's ends, 2 px in from the ring's sides. The second row's CC numbers follow the **F bank + M3 page group** (`CC1`–`CC16` / `CC21`–`CC36`), which is what the old bottom legend used to hint at: **the control-button legend is gone in this mode** so the second dial row gets the room. **ENCMODE3 keeps the plain label/value screen** (its pads are the channel overlay, not the knobs)
- **ENCMODE4 — `FLAVOR` (per F bank)**: the second row's drawing is a choice — **DIALS** (as above), **BARS** (a horizontal level bar per CC, which reads better for a volume / expression number), **ENVELOPE** which splits the row in two with a blank band between them — in the `ENC1` column the **filter** — drawn in a rectangle the size of that cell, with the curve inset inside it (it is the shape its two dials are about, so it owns the whole cell): a low-pass curve drawn in dB — a passband across the middle of the frame, a resonant peak rising into the headroom above it at the corner (the cutoff CC moves the corner, the resonance CC the peak — and even at full resonance the peak stays clear of the band's top, so it draws as a spike instead of a flat top), and a fall below it; the passband bends into that fall over a soft knee instead of meeting it at a corner, so the shape reads as one continuous curve rather than a flat line and then a descending line. There is no flat tail: the curve ends where the response leaves the band, and the fall has the same width at any cutoff. It carries no readout of its own, because those two numbers are the `ENC1`/`ENC2` dials right above it. On the right the **ADSR** of **ENC5 = attack**, **ENC6 = decay**, **ENC7 = sustain**, **ENC8 = release** at half the row's width: a straight attack, decay and release that bend like a real envelope, and a flat sustain. The envelope is laid out left to right, so the **end of the release moves with the release knob** — a long release reaches further right, a short one stops earlier — while never running into the tile's right edge, and a tight bar with **A / D / S / R** sits under each stage. **LFO** takes the same split — the **same filter**, in the `ENC1` column — and draws one **still waveform** on the right half, the shape a modulator would have: **ENC5 = depth** (the height around the centre line, `0–100 %` — at 0 it is a flat line), **ENC6 = rate** (`0.01–10 Hz`, and it sets how many cycles fit across the row, so a high rate squeezes the wave), **ENC7 = shape** (`SINE` / `TRI` / `RISE` / `FALL` / `SQUARE` / `RANDOM`, the last a stepped sample-and-hold with at least four steps across the row so a slow random LFO does not read as a flat line) and **ENC8 = sync** (`HZ` free-running with fractional cycles, `BEAT` whole cycles locked to the beat with a rule at each boundary, `TRIG` one shot, a single cycle whose width is one cycle at the current rate — the rest of the row is the flat line the shot leaves behind, with a rule where it ended, so `ENC6` stays visible instead of every rate drawing the same full-width cycle). Nothing animates — the knobs only change the picture, which is why it can be read at a glance while the truth stays the CC value. Its four readouts sit on **one line** under the row as **`label: value`** — `DEPTH: 75%` / `RATE: 0.9HZ` / `SHAPE: RANDOM` / `SYNC: BEAT` — the value directly behind its own colon rather than parked at the far end of a slot, and the line **right-aligned**: the last value ends at the panel's right edge and the four pairs run left from it, so the line stays on one row and no longer shifts whenever a value changes width. **Hold an F pad** and the row previews that bank with **ENC1 = FLAVOR** (one state per **`encStep`** step — the shared list-knob rate, `12` counts ≈ 8 states a turn on the panel's detentless knobs, one detent on quadrature ones — so a nudge no longer walks the whole four-state list; no wrap), every other knob idle for the length of the hold. Each F bank keeps **its own** flavor **per track type** — the set that applies is the **edit channel's TRACK** (DRUM / MONO / POLY), so a drum page can draw `LEVEL` bars while the same channel's poly page draws `ENVELOPE`, and switching `TRACK` on a channel brings that type's own choices back instead of overwriting them (twelve flavors in all: 3 track types × 4 banks). The row always draws the edit track's armed bank's — the hold (and the knob itself) arms the bank being edited, which is what makes the flavor stay on screen and come back with that bank when you leave and re-enter ENCMODE. It is a drawing choice only — the CC numbers, the stored values and the MIDI send are untouched — and the choices are **remembered across power cycles**: they are written to their own small EEPROM block (`2184..2197`) when you let go of the F pad that was editing them — **and by ENCMODE4 + `REC`**, which saves the CC values and every flavor together (not on every detent, so a knob turn never waits on the write; a pending edit is also flushed by `loop()` once no F pad is down) — and restored at boot with the CC values. A board that never stored one still boots to dials. The flavor belongs to the **bank**, not to the variant: **ENCMODE 1, 2 and 4 all draw the armed bank's flavor** (clicking out of ENCMODE4 back to plain ENCMODE keeps the `BARS` / `ENVELOPE` row on screen), and only **ENCMODE3**, whose pads are the channel overlay, keeps its plain label/value screen. The `FLAVOR` menu itself stays on the variant-4 F hold
- **PREV = `CC CONFIG` page**: a click turns the whole grid into the same eight CC numbers in text — caption `ENC1`–`ENC8`, value `CC17`–`CC4` — because the ring's bottom notch only leaves room for a 4×6 caption. The page prints whatever `encCcNum()` returns at that moment, so **F1–F4** and the **M3** page group move the numbers live, and the header names the encoder channel they are sent on. It is informational — every knob keeps sending while it is up — and a second click goes back to the dials. Like every page it dies with the screen it covers: a mode/variant change or the NEXT Live overlay closes it
- **Step pads = channel picker (locked) — plain ENCMODE**: the 16 pads are the encoder's 16 MIDI channels (dim yellow, the selected one bright yellow, left header `CHANNEL SELECT`), and a press sets the encoder channel, shows `Channel N` and repaints the dials, so the CC bank can be addressed without holding ENC into ENCMODE3. The M1 (drum-voice mute) and M2 (channel mute) overlays still take the row while held and give it back on release
- **ENCMODE4 leaves the pads on the sequencer** — playhead, step states and the M1/M2 overlays behave as on any other screen, so the knobs can be worked while the pattern runs and the steps stay visible. Channel changes there come from the momentary variant 3 (hold ENC)
- **ENCMODE4 + REC** saves all 36×16 knob values + channel to EEPROM (an older save is ignored, defaults stay)

## ENCABLETONMODE — the Live bridge (NEXT)
- **NEXT** taps a latched overlay on top of ENCMODE: the pads become Ableton Live's **clip
  slots**, the knob captions become **Live's parameter names**, the values become **Live's
  display values**. Tap NEXT again and ENCMODE is back exactly as it was — this is an
  overlay, not a fourth mode family, and its state is RAM only
- the knobs keep sending CC — but in this overlay they send the **new automap block
  CC 64–71**, never 17–20/1–36: every ENCMODE dial, its per-CC-per-channel memory and every
  MIDI-learn map you made there are untouched
- **PREV** (hold) = the 16 **tracks**; **M3** = swaps the F row to the clip actions
  (fill track / fill scene / stop track / stop all); **F1/F2** = parameter bank,
  **F3/F4** = device
- it needs the companion remote script in `Remote Scripts/Teensy2048/`; without it the
  overlay says `Link Down Check MIDI` and the knobs still send CC 64–71
- clip content, LED meanings, the protocol and the limits:
  [ENCABLETONMODE](link.md)
